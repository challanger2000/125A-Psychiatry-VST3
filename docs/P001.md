# P001 — PARANOIA reverse-event DSP proof of concept

Status: **prototype, not a VST3**. Targeted experimental implementation to assess a distinctive sound *before* GUI development. Sources: `src/paranoia.hpp`, `src/paranoia.cpp`. WAV renderer: `tools/render_paranoia.cpp`. Tests: `tests/test_paranoia.cpp`.

## Distinguishing audio design
- The input is held in a stereo *past-audio* ring buffer. Time-, transient-, or hybrid-triggered events play an earlier fragment in reverse. No attempt is made to claim future audio can be reversed without lookahead latency. This design adds **zero lookahead latency**; processing includes natural delays in the wet effect.
- A parallel comb path has bounded nonlinear feedback; left/right delays differ to produce spatial unease. The reverse-event path is crossfaded in/out; the macro morphs the entire composite.
- `Pattern::Every`, `Alternating`, or `Random` decides which events actually reverse. Time triggers support milliseconds or a BPM-derived beat division; transient detection is adaptive and internal.
- THERAPY remains the independent, inverse Dry/Wet control. The zero-macro signal and 100%-therapy signal must be unchanged for finite normal-range input.
- Call `prepare(sampleRate)` outside the audio thread, then `setSettings` and `process`. `process` must not allocate or block.

## How to test

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
# Windows:
./build/Release/render_paranoia.exe artifacts/Paranoia_P001
# Linux/macOS:
./build/render_paranoia artifacts/Paranoia_P001
```

The renderer generates a **synthetic probe** (bass pulse, repeated transient, slight stereo detune), then writes separate stereo 48-kHz 16-bit PCM `*_dry.wav` and `*_wet.wav`. These are *demonstration assets, not evidence that musical quality is approved*. Use the same gain when comparing.

## Automated tests
- zero effect = bit-exact signal for finite input;
- 100% THERAPY = exact dry signal;
- trigger counts/active reverse samples, millisecond/tempo modes, alternating patterns, input transient triggers;
- block-size invariance at 137 vs 1024 samples;
- numerical stability, finite outputs at 192 kHz including invalid input;
- a minimum nontrivial measured wet/dry signal difference;
- `CHECK` remains active under release builds (does not use disabled `assert`).

## Limitations and review gate
- Only **PARANOIA** is prototyped, the other eight macros remain unimplemented.
- No interactive VST3, GUI, host transport synchronization, preset state, real photo assets, or DAW test yet.
- The reverberant/darkness and multiple event interaction remain exploratory, and the audio is **not** auditioned/approved by the user.
- Macro smoothing occurs over ~15 ms, not instantaneous. Past-buffer reverse may be zero when there is not yet enough captured audio.
- Maximum host block size, realtime allocation instrumentation, and CPU measurements remain to be added for an actual VST3.
- Evolve this algorithm only if listening demonstrates a truly distinctive and musically useful result; otherwise replace rather than decorating it.

## Inspired by Backmask — original implementation
Freakshow Industries **Backmask** demonstrates event-based reversal triggered by time, tempo or input level and event patterns. This project implements a separate original past-buffer algorithm, not copied Backmask code, audio or graphics. It does not implement Backmask's future-audio Time Align feature.
