## Findings carried forward from P010

Actual **Windows VST3 Processor::process** output, not a separate plug-in imitation, proved that all nine sound worlds genuinely altered the source and that the macro endpoints and THERAPY inversion work. It also exposed avoidable output level differences when one macro alone was at **100%**, THERAPY at **0%**, all others disabled.

## DSP correction

Only three real DSP classes changed, all in `src/`:

- `Dissociation::process()`: the isolated reverse-grain wet branch `displaced` is multiplied by `1 + 0.80 m²` before the macro's regular Dry/Wet crossfade.
- `Hallucination::process()`: the true analytic/spectral `transformed` branch is multiplied by `1 + 0.65 m²`.
- `Panic::process()`: the electric wet impulse branch is attenuated by `1 / (1 + 0.25 m²)`.

Here `m` is the internal smoothed/curved macro level (normalized 0–1). **These factors are exactly 1 at 0 %**, so the unchanged natural Dry endpoint remains bit-exact. At 100% the engine's own wet output is used **without any parallel original Dry injection**. Changes are arithmetic only: no memory allocation, latency or new processing threads.

The single global THERAPY mixer is unchanged: **THERAPY 0% = fully processed; THERAPY 100% = exact original Dry**. A 12-ms smoothing period remains relevant to moving/automated transitions; static endpoints are exact.

## Test method and acceptance

The repeatable P010 test `tests/test_vst3_audio_path.cpp` is retained and strengthened: it renders 180 cases using **actual VST3 ProcessData**, each of five generated stereo proxies at 20/50/75/100% for each of nine macros. Alongside the previous 45 direct-engine 100%-Wet sample comparisons, 0%-Dry bit equality, Bypass, inverse THERAPY and gain-placebo negative control, the test now fails if any **100%-Wet gain is below −8.0 dB or above +6.0 dB** for *those five reference signals*.

## Scope boundaries

This is a **gain-staging correction supported by objective references**, not a declaration of musical taste, final crest factor/true peak control, spectral alias rejection, automatic level matching across arbitrary real source recordings, or large-multiple-instance CPU certification. P006 checks peaks and DSP timing at **20/50/85%**, not at every possible full-Wet real-world level. A dark CRT GUI is present, but the final aged-clinic visual assets are outstanding. No Studio Pro real-session QA or user musical acceptance has occurred.
