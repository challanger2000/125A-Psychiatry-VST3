# 125A PSYCHIATRY P030d – lokaler Performance-Test
Windows x64. ZIP komplett entpacken, Studio Pro und andere rechenintensive Anwendungen schließen, start.bat doppelklicken. Kein Administrator, keine Installation, keine Änderung an Plugin-Ordnern. Das mitgelieferte P030d-Bundle wird direkt geladen; SHA256 der DLL wird vor dem Test geprüft. Die 24 Fälle (44,1/48 kHz, 256/128/64 Samples, eine/vier seriell berechnete Instanzen, repräsentativ/alle zwölf hoch mit dichter Automation) erzeugen je 10 Sekunden Audio nach Warmup. Ausführung kann je nach Rechner länger dauern. Alle Tests laufen auch nach Zeitbudget-Überschreitungen weiter. Nach Abschluss RESULT-* Ordner mit report.txt, measurements.csv, system.txt und exit-code.txt zurückgeben. 0 bedeutet keine Callback-Rechenzeitüberschreitung, 4 bedeutet mindestens eine, sonst Testfehler. CSV enthält Callback-Wallclock, Thread-Zyklen, Startverspätung und synthetische Finish-Deadline getrennt. Das künstliche Scheduling, serielle Mehrinstanzlast und dichte Automation sind nicht identisch mit einer DAW; keine ASIO-Messung, keine Aussage über tatsächliche Dropouts. Finaler Studio-Pro-Test bleibt erforderlich. Produktstand 4828981be7013e8dcba711dce29d97cd7673ad72, v0.9.28. Keine Produktänderung.

Native Treibermessung: START-ASIO.BAT starten, Yamaha Steinberg USB ASIO auswaehlen, 24 Faelle soweit vom Treiber unterstuetzt. Echte Hardware-Callbacks; synthetisches Stereo-Signal wird durch die DLL verarbeitet, physische Ausgaenge bleiben stumm. Callback-Zeit, Intervalle, Samplepositionen (wenn geliefert), Treibermeldungen, Overload/Resync und Latenzangaben werden protokolliert. Nicht unterstuetzte Blockgroessen oder Raten sind NOT RUN/INCOMPLETE und nie PASS. Falls der Treiber die Puffergroesse nur in seinem Control Panel einstellen laesst, diese dort aendern und erneut starten. Der Test versucht die urspruengliche Sample-Rate wiederherzustellen. Kein physischer Loopback, kein DAW-Projekt-Test. Testhost driver_test.exe GPL-3.0-only, separat vom unveraenderten Produkt; SDK-Quellen und exakte Build-Anweisungen im beigefuegten Quellpaket bzw. Repository. Hardwarelauf in CI nicht moeglich, nur Selbsttest der echten DLL-Verarbeitung.

Update 2: ASIO uses ONLY the currently configured hardware sample rate and preferred buffer (64/128/256), four cases per run. It does not change the rate. One driver is selected automatically. Full duplex when available, input not read or recorded. Driver reset or rate-change request aborts the current attempt, closes the driver fully, and retries up to twice. Interrupted attempts are logged separately, never counted as completed. Change rate/buffer in the driver panel between runs if needed.
